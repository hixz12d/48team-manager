# UI 第三批实施记录

第三批按 `UI改动大纲.md` 第 3 章和 2.7 实施。保留原生 JS/CSS、主题与接口执行流程。本批仅本地实现和隔离回归，未部署。

## 界面调整

- 自动轮转折叠为状态行，显示开关、范围、日限和异常数量，展开后保留原设置入口与阻塞团队链接。
- 常用筛选保留搜索、用途、检测状态；团队与 Sub2API 条件、核对、同步全部团队收进“更多筛选”，展示生效数量。
- 普通账号行在专项数据中不超过 64px。邮箱与本地用途并列，授权状态短标签，5h/7d 额度和重置星期同列，超过 6 小时标记旧快照。
- 远端 ID、成本和完整状态说明转入提示和账号详情，保留行内 Sub2API 推送/更新入口。未配置 Sub2API 时移除整列，顶部给设置入口。
- 1024px 等窄桌面宽度操作列固定右侧，表格内容横向滚动。页码按完整团队打包，超大团队单独一页，不拆开团队；额度排序先比较各团队最差成员，再在团队内排序。
- 团队头部主要操作为“管理团队”和更多菜单。同步、代理、到期日期、次数校正和“移除本地记录”保留在菜单；原删除确认仍清楚说明不会解散官方团队或删除远端账号。
- 头部保留席位、到期、切换计数和异常摘要，不再常驻直连代理提示与加一按钮。次数校正继续使用原控件，保留请求去重、跨标签更新和北京时间午夜重置。
- 抽屉顺序为进度、成员、主动作/单个表单、团队信息、危险操作。母号置顶，其余按待处理、在席、待邀请、已离队排序；账号详情入口融入成员邮箱。
- 邀请、补充、轮转仅展开一个表单，切换时保留草稿，提交收起后由任务进度接管。
- 轮转下拉仅列出本地可识别的在席子成员，排除母号、邀请中、未接入、冲突、待同步和已离队记录；当前凭据实际 401 排在周额度用尽之前。选项显示邮箱、5h/7d 额度、授权状态，确认后才发请求。
- 邀请与补充共用角色控件。补充接口原本已支持 role，本批显式传入。仅一个已离队成员且角色明确时预选，否则要求选择，不猜测原席位。
- 接码号在更多参数中，留空使用已配置号池；说明号码与链接的分隔格式。移除未展示但被读取的 force/skip_invite 控件，普通邀请继续提交 false。
- 到期入口展开团队信息内的编辑区；日期摘要与保存结果同步。代理目录改为展开邀请更多参数时才加载，打开到期区不再读取无关目录。
- 账号行关联到明确 account_id 的任务时显示进度徽章。后端已保存的入组中断可进入任务详情或“继续此邮箱”，只预填草稿，不自动提交、不重新领号。
- 账号菜单按常用、同步与检查、危险操作分组；沿用已有可见性与确认规则。

## 数据口径与边界

- 总览和账号页“待处理账号”共用 portfolio 的 `needs_attention`、`attention_reasons`、`attention_breakdown`。按账号去重，原因可重叠，包括授权、入组中断、额度、检测、远端、身份、团队同步。总览原有资源/任务提醒保留在单独折叠区。
- 后端改动限于本地数据库的只读呈现，不改邀请、补位、踢人、轮转、官方角色决策或写入流程。
- **切换次数不等于自动轮转次数。** 核对 `member_handoff.count_switch_once` 后发现，现有计数用于授权闭环及手工补记，和自动轮转日限分别存储。因此保留“今日切换 N 次”，不虚构“今日轮转 N/2”。校正入口当前只能增加，界面明确说明。
- 后端 workspace read model 的 `rotation` 当前可能为空。前端在没有明确禁止字段且存在母号与候选成员时允许展开；真正执行仍由后端重新核对席位和资源，不把列表快照当作操作授权。
- 原有接口仍在请求中同步执行，按任务 ID 精确追踪属于下一批方案 B。
- 保留历史账号与官方成员数据来源的区别，官方 Owner 角色不能推断本地母号身份，缺额度不显示为 0。

- 切换计数卡头只读；写入测试进入“校正今日切换次数”，仍完整覆盖原有守卫和午夜逻辑。

- 原成员测试的两个 mock 缺少已经存在的 `seat_intent` 参数，本批同步补齐 mock 签名，未改生产流程。

设计具体性：围绕官方额度巡查、团队席位和成员操作组织信息，保留现有视觉，不换框架或引入装饰。认知负担明显降低，主动作条只有邀请、补充、轮转三个入口。账号菜单仍有多项功能，通过分组承接而不删除功能。

优势：首屏筛选一行可扫读；成员与额度在操作现场；表单切换不丢草稿。运维用户减少了记邮箱和滚动距离；键盘用户保留确认/返回焦点，低对比旧侧栏仍是后续问题。
