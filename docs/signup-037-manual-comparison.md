# 注册助手0.3.7：对照手动流程后的修正

## 对照依据

2026-09-20，用户确认本轮未启用0.3.6插件，邮箱、验证码、姓名和年龄均手动填写，注册后成功取得OAuth refresh token。完整观测与回查见 `lava1-manual-recording-20260920.md`。用户认为新标签页不是重点，故本次没有改变授权标签页策略。

本轮不是账号风控因果实验：不同账号、不同时间等因素仍存在。修改只针对可在本地模拟浏览器复现的行为缺陷，不宣称能避免手机验证。

## 修改及复现结果

| 问题 | 修改前复现 | 0.3.7处理 |
| --- | --- | --- |
| 提交无加载动画 | OTP和资料表单各自第一次提交后，旧版继续补点，模拟提交处理次数达到3 | 点击后只要已收到submit，就保留等待，不再自动补点；45秒未前进时暂停。后台和托管状态机也阻止该回执补点 |
| 资料页最终按钮 | Finish creating account没有进入统一按钮识别，填写校验产生submit后无法恢复正常提交 | 统一识别Continue、Verify、Create account、Finish creating account等按钮，用于提交和等待判断 |
| 同页切换复用输入框 | 邮箱输入框变为姓名输入框后，旧任务继续写入邮箱并可能按旧阶段提交 | 字段和按钮绑定路径、表单结构；旧任务失效后重新识别当前步骤，不再用仍连接的旧节点兜底 |
| 取码期间页面切换 | 异步收码/后台调用返回时，原输入框可能已经属于下一步 | 收到响应后再次检查原字段引用，失效则放弃这一步操作；模拟测试确认不会把验证码写入姓名 |
| 完成后的注册轮询 | 完成后内容脚本仍定时读取注册状态 | done/stopped后停止循环并解除页面事件监听，保留结果卡片 |

只点击无响应且没有submit、加载、校验错误、路径/表单变化的按钮时，仍保留有限补点。填写阶段单独出现的DOM submit可能只是字段校验，本次手动记录本身也包含这类事件，不能把它等同于服务端重复请求；原有8秒空闲观察逻辑保留。

保留输入字符间隔、资料生成、接码接口、入口回退及已有用户改动。未模拟硬件身份，合成事件仍是合成事件。共用内容脚本的本地托管状态机同步增加submitted保护，没有部署VPS。
