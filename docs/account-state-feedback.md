# 授权反馈与 Sub2API 账号状态

账号列表现在同时展示本地授权/官方额度、Sub2API 远端存在性及运行状态、Sub2API 计费快照。这三种数据独立判断；旧额度正常不代表远端账号还存在。

## 页面行为

- 官方已加入但未接入本地的成员，行内提供“接入并授权”。沿用现有成员接入和身份校验，不增加额外邀请。
- 团队内完成 OAuth 后同时刷新团队侧栏和主列表；独立授权也立即刷新列表。后台操作从页面重载恢复后完成时，同样更新显示。
- 凭据已保存、额度任务尚未结束时显示“已授权 · 等待额度检测”；不把等待检测当成需要重新登录。新凭据不会复用旧凭据的 401 结论。
- 刷新职责确实委托给 Sub2API 时，本地只有 AT 不再单凭缺少 RT 显示“待完成 OAuth”。正式交回 Team 后，恢复本地 RT 要求；实际 401 等错误仍正常显示。
- Sub2API 列展示远端正常、暂停、授权失效、限流、临时不可调度、已删除/不存在、身份待核对或未知，附远端 ID 和核对时间。提供远端状态筛选和“核对 Sub2API 状态”按钮。

## 同步与可靠性

页面可见时每 30 秒请求一次远端状态核对，并立即重新读取列表。页面隐藏时暂停，返回页面后立即恢复。后台每 60 秒兜底同步。自动请求在服务端共用 30 秒冷却；手动核对跳过冷却，并发请求合并。网络请求有 20 秒总时限。

只有完整且格式有效的 Sub2API Admin 账号列表能证明某个绑定的远端 ID 不存在。列表接口 404、认证失败、超时、断网、无效或不完整分页，都显示核对失败，不当成账号删除。失败时保留上次观察并标记旧状态；超过 90 秒的快照同样显示待更新。状态读取不会删除或解绑账号，不修改远端调度开关、Token 或 Team 成员。

远端状态使用独立的 `sub2api_account_status` 本地表，不占用凭据同步回执表。连接地址或绑定身份变化会使旧观察失效；核对中绑定变化时丢弃对应结果。表不保存凭据和远端原始错误文本。

远端运行状态按远端当前状态字段判断，历史额度百分比和旧错误文字不会覆盖正常状态。官方额度和 Sub2API 计费仍使用各自的查询与刷新机制，计费没有改为每 30 秒全量查询。

## 启动与检查

新表由现有启动初始化自动创建，无需重建数据库。部署后首次打开账号页会发起核对；没有配置 Sub2API 或没有绑定时不发远端请求。

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_sub2api_status tests.test_quota_health tests.test_account_deletion tests.test_unified_accounts -q
node --test tests/account_feedback_ui.test.cjs tests/management_ui.test.cjs tests/runtime_ui.test.cjs
.\.venv\Scripts\python.exe -m tests.browser_account_feedback
```

浏览器回归使用隔离 SQLite、FastAPI TestClient 和模拟外部响应，覆盖直接接入、两条 OAuth 完成路径、自动核对远端删除、状态筛选、网络失败、暂停回读及桌面/窄屏布局。不会登录真实账号或修改真实 Sub2API。
