# 计划：总览收入合计、今日收入、近 7 天收入

## 需求

团队卡上已经有"已入账 ＋ 在跑"，但总览上看不到所有团队的合计，也看不到"今天赚了多少""近 7 天赚了多少"。做完后，总览顶部能直接看到四个收入数：今日收入、近 7 天收入、本月入账，以及团队收入合计（已入账 ＋ 在跑）。

近 7 天的数要算准，就得知道每个号每天各赚了多少，包括已经被换掉的号。所以新增一份"每日收入记录"：每个号每天一笔，号离队、绑定被删也保留。

## 对齐结论

| 事项 | 结论 |
|---|---|
| 总览顶部收入格 | 依次为：**今日收入**、**近 7 天收入**、**本月入账**（保留现有口径）、**团队收入**（替换原"累计收入"格，显示 `已入账 $X ＋ 在跑 $Y`） |
| 团队收入合计 | 口径和团队卡那行一样：已入账 = 账本累计（现有 `revenue_totals.total`），在跑 = 所有团队在席成员（含母号）全程 U 之和 |
| 团队卡 | 不改，不加今日 / 近 7 天 |
| 今日 / 近 7 天怎么算 | 还在绑定中的号：用后台 5 分钟同步拉到的"今日"和"自然 7 天"快照；已不在绑定中的号（离队、绑定已删）：用每日收入记录。两部分相加，同一个号不重复算 |
| 每日收入记录 | 新表，每个远端账号每天一笔，存当天累计 U。写入时机：① 每次 5 分钟用量同步成功时写当天这一笔；② 离队记账（`settle_binding`）时实时读一次再写，离队前最后几分钟也算进去。只增不减（取新旧较大值）。不随团队 / 账号 / 绑定删除而删除 |
| 历史补录 | 上线时，还在绑定中的号靠现成的 7 天快照，当天就准。上线前已离队的号：如果 Sub2API 能按天查历史且远端还在，启动时补最近 7 天；补不到的，近 7 天的悬停提示写"离队号从 X 日起统计"（X = 每日记录最早一天） |
| "一天"的边界 | 按 `TIMEZONE` 设置（默认北京时间）0 点。开发时要核对 Sub2API "今日"是不是同一个边界，不一致就停下报告，不硬凑 |

**按常规处理的细节**：
- 只算 U（Sub2API 用户扣费 `user_cost`），不算账号成本和利润；所有已验证的 Sub2API 绑定都算，包括母号和未分配的号。
- 数据有缺口时照搬团队卡的做法：有号还没同步到时，悬停提示"x/y 个号已同步"；超过 30 分钟没更新标"旧快照"；一个数都拿不到显示"—"，不显示 $0。
- 前一天留下的"今日"快照（同步窗口不是今天）不算今天的数，计入"未同步"。
- "本月入账"悬停说明"本月离队号入账之和，不含在跑"，避免和今日 / 近 7 天的口径混淆。
- 只读 Sub2API，不写；离队记账多读的那一次失败不阻塞离队流程，退回用本地"今日"快照。
- 页面跟随总览现有的刷新节奏，不新增轮询。

**不做的事**：
- 不做每日收入的历史页面或走势图（数据先存着，以后要看再做）。
- 团队卡、团队抽屉不加今日 / 近 7 天。
- 不改"已入账"账本的记账规则和"本月入账"口径。
- 不能手动改每日记录、不能删。

**接口约定**（part-1 产出、part-2 使用）：`GET /api/overview` 的 `summary` 在现有 `revenue_total`、`revenue_month`（金额字符串）之外新增三个对象，形状相同：

```json
"revenue_running":   {"user_cost": "12.37", "synced": 9, "total": 10, "stale": false, "note": null},
"revenue_today":     {"user_cost": "3.20",  "synced": 9, "total": 10, "stale": false, "note": null},
"revenue_seven_day": {"user_cost": "41.08", "synced": 9, "total": 10, "stale": false, "note": "离队号从 10-03 起统计"}
```

- `user_cost`：金额十进制字符串；一个数都拿不到时为 `null`（前端显示"—"）。
- `synced` / `total`：在绑定中的号里，有效快照数 / 总数。`total` 为 0 时前端不提示覆盖率。
- `stale`：任一参与计算的快照超过 30 分钟未更新。
- `note`：额外说明（如离队号统计起点、Sub2API 日边界说明），没有为 `null`。

## Part 总览

| Part | 内容 | 依赖 | 可以同时做的 Part |
|---|---|---|---|
| part-1-backend | 每日收入表、同步 / 离队写入、启动补录、总览 summary 新字段、预览示例数据 | 无 | part-2 |
| part-2-overview-ui | 总览顶部四个收入格的模板、渲染、悬停提示和样式 | 无（按上方接口约定开发） | part-1 |

**执行顺序**：两个 Part 文件不重叠，可开 2 个窗口同时做；part-2 想在预览里看到真实数据，需等 part-1 完成后再用预览核对一次。

## 上线注意

- 新增表 `sub2api_revenue_daily`，由启动时 `bootstrap_schema` 自动建，无单独迁移命令；按 RUNBOOK 部署前先备份 `data/team48.db`。
- 启动后台补录会读 Sub2API（只读，仅限最近 7 天内离队的号），日志关键字 `revenue daily`。
- 上线当天的近 7 天收入里，上线前离队、又补不到历史的号会缺；悬停提示会写明起算日，7 天后自然补齐。
