# Part 1：真实跑一轮手动轮转

**状态**：待开始

**所属计划**：[README](./README.md)

## 目标

在生产上用一个真实旧号和一个新邮箱完成一次手动轮转，确认新号可用、旧号远端记录已删、今日切换 +1。

## 只读参考

- `docs/RUNBOOK.md`（备份、健康检查、排障）

## 要点

- 新邮箱不能是旧号或母号；预检确认框里的角色和席位要和官方一致。
- 遇到手机验证会停在待处理，这是预期行为；人工处理后从任务详情点"继续轮转"，核对它只执行未完成阶段。
- 新号可用前，旧号的 Sub2API 记录必须仍在。

## 步骤

1. 向用户确认团队、旧号、新邮箱，并取得真实写入批准。
2. 按 RUNBOOK 备份数据库。
3. 在团队抽屉发起手动轮转，记录 Operation ID。
4. 跟踪任务步骤直到完成或待处理；若待处理，按提示处理后"继续轮转"。
5. 核对：官方团队成员、Sub2API 新号可用且旧号已删、本地旧号档案仍在、今日切换次数 +1。

## 完成标准

- [ ] 任务状态为成功，步骤 `paused` → `counted` 全部完成
- [ ] Sub2API 新号可用、旧号远端记录不存在
- [ ] 今日切换次数只增加 1
