# 48 Team Manager

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

单一使用者：项目作者本人，作为运维操作员在桌面浏览器（Windows，1440px 以上宽屏为主）使用。规模约 10–40 个 ChatGPT Team、几百个账号。手机端只需"能看、不塌"。

## Product Purpose

自用的 ChatGPT Team 运营控制台，不是 SaaS、CRM 或质保平台。日常：

1. 巡查各团队母号 / 子号的官方 5h / 7d 额度，判断谁该轮转。
2. 发现授权失效（401、缺刷新凭据）并重新授权；多数授权由浏览器插件 `extensions/chatgpt-signup` 完成。
3. 踢人 + 邀请 / 补位 / 轮转，并能看到长任务走到哪一步。
4. 配置外部服务（Sub2API、iCloud HME、Cloudflare 临时邮箱、手机号池）并排查同步失败。

成功标准：一眼看到异常，两三步内处理完，长任务随时知道卡在哪。

## Positioning

三个轴永远分开、互不推断：

- 官方计划：`free` / `plus` / `pro` / `team` / `business` / `unknown`
- 团队角色：`owner` / `admin` / `member` / `unknown`
- 本地用途：`mother` / `child` / `standby` / `free` / `disabled`

邮箱后缀、姓名、团队前缀都不是身份依据，最多作提示。真相来源：本地用途看本地库；团队、角色、额度看 OpenAI 官方接口；账号绑定、计费用量、代理目录看 Sub2API（代理目录只读）；导入 codex-rs 的号由 codex-rs 续期；HME 别名和手机号看本地租约。

## Operating Context

- 单容器（FastAPI + SQLite + APScheduler + Playwright），只绑 `127.0.0.1:8018`，经 Nginx 暴露。
- 长命令一律返回 `operation_id` 后台执行，步骤持久化；刷新、关浏览器后可恢复，容器重启时进行中的任务标为待人工处理。
- 自动额度检测、自动重授权、自动轮转默认关闭，需在界面显式开启。
- 本地预览：见 [ARCHITECTURE.md](ARCHITECTURE.md#本地运行)。

## 关键业务规则

**手动轮转**
- 新邮箱必填，不能与旧号或母号相同；先只读预检，确认框显示实际继承的官方角色和席位。admin 或未知角色 / 席位直接停止，不降级不猜。
- 顺序：预检 → 暂停旧号远端调度 → 移出官方团队 → 邀请新邮箱 → 注册并入组 → 同页 OAuth → 推送 Sub2API 并回读可用 → 删除旧号远端记录 → 计数一次。
- 新号确认可用前绝不删旧号远端记录；旧号本地档案始终保留。不领 HME，邮件验证码只读 Cloudflare 邮箱；遇手机页按下方"插件接码"自动用号码池。
- 预检先按完整 Sub2API 目录自动整理旧号本地绑定：远端已删的绑定直接清掉；远端恰好一个邮箱、团队都对得上的账号自动记为已验证。对不上（同邮箱多个、团队不一致）才停下让人核对。只改本地记录，不写 Sub2API。
- 移出后只有回执明确显示空位收费（账单回执、需替换席位、非免费空位）才停下等人确认；回执为空或不明确时直接补位。
- 遇手机 / 人机验证或写入结果不明就停下，保留同一邮箱和进度（不保留浏览器现场）。团队有未完成轮转时不能再发起轮转、邀请、补位或踢人，归档也解除不了；只能从原任务"继续轮转"，或"结束轮转"。
- 结束轮转（人已在别处换好或决定不补）：先只读核对新邮箱官方是否已入组、新号 Sub2API 是否可用、旧号远端记录是否还在，结果列进二次确认框，不通过也允许结束。确认后任务记为"已人工结束"、解除团队锁定并排队同步团队；不改官方团队、不写 Sub2API，旧号远端记录需自行处理。仅当官方确认新邮箱已入组、且该成员和本轮转都没计过数时，今日切换 +1。

**自动轮转**
- 范围：选中团队或全部团队；每团队每日上限默认 2（0–50，0 = 不轮转），按北京时间统计已确认移出次数，失败也占名额。
- 触发：7d 额度确认 100%、当前凭据确认官方 401、或明确 `account_deactivated`。5h 用尽、403、网络错误不触发。
- 补位空邮箱由 HME 领取；出现手机页时用号码池接码（extension 方式见下方"插件接码"）。推送未确认时只重试推送，最多 5 次（1/2/4/8 分钟退避）。

**轮转注册方式**（设置 `ROTATION_SIGNUP_RUNNER`，手动 / 自动轮转共用）
- `playwright`（默认）：服务器 Playwright 浏览器注册和授权。
- `extension`：服务器用 Chromix 指纹浏览器加载同一份注册插件完成注册和同页授权，出口仍用母号代理，时区按出口所在地固定。遇手机页按下方"插件接码"处理；接码不成或遇人机验证就关浏览器停下（保留同一邮箱），人工授权后点"继续轮转"。带账号密码的 HTTP 代理不支持，在踢人前就拒绝。
- 邀请、补位、控制台注册、重新授权不受这个开关影响。

**插件接码**（本机插件带 Team48 令牌时、服务器运行器的手动 / 自动轮转）
- 注册或授权遇"添加手机号"页：向服务器领一个号码池里的号，填 10 位本地号码，用页面隐藏字段核对完整号码，发送方式不是短信才点一次 Text Message，然后点 Continue；服务器读短信，只把领号后新到的验证码交给插件填写。不检查国家（+1 加拿大区号会自动切成 Canada，属正常）。接码链接只留在服务器。
- 号不能用（无效、刚被用过、切到 WhatsApp、点 Continue 后 20 秒没反应）就记一条接码记录、刷新手机页换下一个号；短信页 90 秒没收到码则点"更换号码"回去换号。一个账号最多换 3 个号；超过、号码池空、找不到"换号码"入口就暂停交给人。轮转"继续轮转"重新计 3 个。
- 账号已绑手机时用本地记录的号码和接码链接，没有记录就暂停。成功后号码用量 +1，号码和接码链接写到该账号。
- 读短信走代理：轮转用运行时代理；本机插件按"账号代理 → 母号代理"取，都没有就暂停。
- 两种手工模式、未带令牌的本机包、服务器 Playwright 注册仍是遇手机页就暂停。

**HME**：只有空邮箱才领别名，手填邮箱不领不打标。规则全文见 [hme-linkage.md](hme-linkage.md)。

**额度与健康**
- 每个"账号 + 团队"单独记录最新检测和最后成功额度；超过 75 分钟、凭据版本变化或最近失败都标"旧"。未知不显示为 0。
- 网络错误、5xx、解析失败不算凭据失效；429 按 Retry-After 等待，手动按钮也不绕过。
- "已授权 · 等待额度检测"不等于要重新登录；Sub2API "核对失败"不等于已删除，要同时显示上次状态。

**团队成员**
- 官方移除只把该团队关系标为已移除，本地账号和凭据保留；已离队账号可用原角色重新邀请。
- 撤回邀请不会踢掉已接受的人；本地解绑只改本地。
- 官方写请求超时或 5xx 返回"结果未知"，先同步核对，不自动重发。

**Sub2API**
- 新建默认：并发 5，分组可多选，代理可选不指定 / 固定 / 按代理分组自动分配；只对新建生效，更新保留远端原配置。
- 任何操作都不清除人工暂停、认证错误、限流；令牌不进浏览器。计划 / 订阅写入目前关闭（合约未验证，显示"未验证，未写入"）。

**codex-rs**
- 一个号只进一边：有 Sub2API 绑定（远端已确认删除的除外）或 Sub2API 刷新委托的号不能导入 codex-rs（`sub2api_bound`）；已导入 codex-rs 的号不能再推 Sub2API（`codex_rs_bound`），轮转、号池遇到这种号也会被拒。要换回 Sub2API，先在 codex-rs 删号再手动重新授权。
- 全局"授权后推送到"（`auth_push_target`，默认 Sub2API）影响重新授权后的推送（账号页 / 团队授权面板）、注册插件接入和手动号池拉入；手动 / 自动轮转固定推 Sub2API，自动补号固定导入 codex-rs。母号不推。
- 导入前本地核对：未停用 / 未归档、AT 有效、有刷新令牌、令牌身份与本地一致；导入后读回远端核对邮箱、团队、用户一致且有刷新令牌。成功后清掉本地刷新令牌和 session token，之后本地刷新改为从 codex-rs 读回 AT，自动重新授权跳过，额度健康不因缺刷新令牌标异常。手动重新授权仍可用，勾推送就重新导入覆盖。
- 首次导入自动挑"最近测试通过、挂号最少"的 codex-rs 代理（并列随机），没有就失败，不直连；同时带设置页的分组 / 并发 / 权重 / 启用。再次导入不带代理和参数，保留 codex-rs 里的原设置。codex-rs 按令牌身份覆盖同一条，结果不明时可直接重试。
- 号离队（踢人、轮转换下、团队同步发现离队）时在 codex-rs 停用，不删除；失败不阻塞离队，踢人结果里记 `codex_rs_disable`。停用过的号再次导入且仍在团队里会自动重新启用。
- 收入账本只统计 Sub2API，不读 codex-rs 用量；删除本地档案不动 codex-rs；"Codex 导出"仍只含 AT。

**codex-rs 自动补号**（默认关；设置：开关、目标数默认 6、每日上限默认 6（0 = 不补，北京时间 0 点归零，失败也占名额）、目标团队勾选）
- 每 5 分钟读 codex-rs 全部 OpenAI 账号（不区分是否 Team48 导入）。算"能干活"：正常且启用、临时限流、只 5 小时额度用完。7 天额度用完立即不算；出错、被停用要连续两轮（间隔 ≥ 4 分钟）才不算；从 codex-rs 消失的自然不算。codex-rs 读取失败这一轮跳过，不当作 0 个去补。
- 出错且仍启用的号自动在 codex-rs 关调度并读回核对，记进"最近自动关调度"；不踢人、不删号、不删本地档案、不自动重新启用（人工到 codex-rs 启用，或重新授权并导入）。7 天用完和已停用的号不动。
- 不够目标时一轮最多发起一个补号，按序检查：今日上限 → 浏览器空闲 → codex-rs 有测试通过的代理 → 勾选团队里可用的（今日切换少的优先，并列取 id 小的；席位未知不排除）→ 号池按导入顺序取邮箱可读、未在任何团队的号。不满足就记"本轮未补号：原因"，等下一轮。
- 补号就是一条来源"自动补号"的号池拉入任务，固定导入 codex-rs，任务页可看可继续；任务成功且导入 codex-rs 成功才算成功。上一个没结束不发起新的；连续失败 2 次自动暂停，点"恢复"或重新打开开关才继续。号池少于 2 个时标红但不暂停；号多出来不处理。

**团队收入账本**
- 只统计 U（Sub2API 用户扣费 `user_cost`），不算账号成本和利润；只读 Sub2API。
- 金额是全程：从 Sub2API 绑定建立到离队；超过 90 天只算最近 90 天并标"仅近 90 天"（Sub2API 上限）。
- 离队出口都记账：手动 / 自动轮转、踢人、踢人并删档、预检整理时丢弃的远端已删绑定，以及团队同步发现的离队（插件或官方页面手动踢人、成员自行离开）。官方确认移出后立即入账，删旧号远端记录前再读一次更新同一条；同步发现的在同步完成后入账，踢人到下次同步之间仍算在跑。
- 启动时自动补记"绑定已验证、成员已离队、账本没有记录"的号。
- 同一"团队 + 远端账号 ID"只有一条，重复读只更新不累加。读取失败不阻塞流程：用本地缓存兜底标"估算"，没缓存记 $0 标"未取到"。
- 账本不随团队或账号删除而删除；不能手动改金额或删账；Sub2API 绑定已被删掉的离队号无从补录。本月按北京时间自然月。
- 今日 / 近 7 天：在绑定的号用 5 分钟用量同步的"今日""自然 7 天"快照，已离队的号用每日收入记录（每号每天一笔，离队时实时补读一次，删绑定也保留），同一个号不重复算。"一天"按 `TIMEZONE` 0 点切，需与 Sub2API 的 `TZ` 一致（不一致时悬停提示写明）。上线前离队、补不到历史的号会缺，提示写"离队号从 X 日起统计"。
- 有号没同步到时悬停提示"x/y 个号已同步"并标"部分"，超过 30 分钟没更新标"旧快照"，一个数都拿不到显示"—"。

**备用号池**
- 导入一行一个邮箱，单次最多 50 个；本地已有的跳过并列出，格式不对的列出。不收密码，登录一律走邮箱一次性验证码。
- 导入时检查 HME 能否读到该别名的收件箱，读不到标"邮箱不可读"，不能拉入，可"重新检测"。导入的号本地用途记 `standby`、运行状态 `available`，现有补位不会取走它，HME 领号也不会领到它。
- 拉入团队一次一个；弹框预选推荐团队（今日切换最少 → 空位最多 → id 最小），可改选；角色默认成员、席位默认团队默认。登录走目标团队母号代理。
- 替换子号：弹框可选该团队一个子号（名单来自上次团队同步，不含母号），选中后角色 / 席位沿用它。任务先把它移出官方团队（本地档案保留，Sub2API 只暂停调度不删），再邀请拉入；席位未知或已满时默认选第一个子号。移出回执显示空位要计费就停在待人工，确认后"继续"。
- 拒绝拉入：号已在某团队入组、团队已知满员且没选替换、团队有进行中任务或未完成轮转、浏览器正被占用、邮箱不可读。
- 入组方式：发出官方邀请后不等邀请邮件，直接打开 Codex 授权链接登录（邮箱一次性验证码），登录即接受邀请入组；官方成员名单确认入组后才保存授权。
- 登录时进入"创建账号"或填年龄 / 姓名页就停下报 `account_not_registered`，绝不改走注册。
- 失败：已邀请或已入组、遇手机页 / 人机验证的停在待人工，号池页"继续"接着同一团队走（已移出不重踢、已邀请不重发）；未注册、满员等记失败。授权登录遇手机页用号码池接码（每号最多 3 个）。推送去向跟随"授权后推送到"（自动补号固定 codex-rs），"继续"沿用上次任务的去向；推送失败不影响入组，到账号页重推 / 重新导入。
- 只有从未入组、无 Sub2API 绑定、无进行中任务的号能"移出号池"（同时删本地档案）。

**插件接入**：插件注册完自动识别所在团队 → 同步 → 接入本地 → 同页授权 → 推送（按"授权后推送到"推 Sub2API 或导入 codex-rs）→ 今日切换 +1。母号不接入；多团队命中或都没命中时让用户手选；授权团队不一致时只保存授权，不推送不计数。同一成员重复授权不重复计数。

## 体验约定

- 技术栈约束：Jinja2 + 原生 JS + 原生 CSS，不引入框架、UI 库或构建链。
- 危险操作（移出官方团队、撤销邀请、轮转、删除本地档案 / 团队）必须二次确认，并写明是否会改官方 Team。

- 分页 20/50/100（账号页默认 20，任务页默认 50）；团队视图按整团队分页。勾选跨页保留，搜索 / 筛选 / 切视图时清空。
- 任务进度在团队卡、抽屉、顶栏任务中心、任务详情共用一个数据源。
- 键盘可完成主流程：Esc 关闭、菜单方向键 / Home / End；状态不能只靠颜色。
- 主题切换（深色 / 浅色 / 跟随系统）跨标签同步。
- 界面语言简体中文，语气直接、简短、工程化。
