# 注册助手 0.3.8：填写后等待与提交复核

## 最终行为

- 所有表单完成填写后统一等待 1 秒，再检查是否仍为原步骤并准备提交。控件可用性、稳定性及点击检查另需少量时间。
- 年龄一致性检查纳入同一次等待，避免刚填完就立即判错。第一次发现校验不通过时，再等 0.7–1.1 秒复核一次；持续不符合要求才暂停。
- 等待前保留原字段与步骤的绑定，等待后重新检查任务、前台焦点、表单和提交状态。包括同一 DOM 节点被下一步复用、取码或日志消息返回时页面已切换等情况。
- 仅填写期间出现的独立 submit 事件，在原有无明确点击、无加载、字段完整且未变、无错误、按钮可用的条件全部满足时，将空闲观察门槛由 8 秒缩短为 3 秒。实际恢复另受 1.5 秒轮询与提交前等待影响。
- DOM submit 不能证明服务端请求是否发生。真实按钮点击后的提交保护、已观察到加载后的等待、次数限制和验证码去重保持生效。

最终改动集中在 `extensions/chatgpt-signup/content.js`、manifest、README 和浏览器回归测试。保留原输入事件方式、键盘监听隔离、进度面板、会话轮询及手机验证暂停逻辑。本轮曾加入的鼠标轨迹、合成键盘事件和轮询节奏修改已撤回。

## 手机验证与 CDP 检查结论

此前将缺少键盘事件、鼠标坐标、DOM 面板和轮询频率直接归因于手机验证，证据不足。辅助输入、粘贴等也可能不产生完整键盘事件；屏幕坐标受窗口、显示器布局和缩放影响。仅凭这些差异不能推断服务端风控结果。

仓库 `docs/managed-signup.md` 已记录用户确认过同一代理出口、HubStudio 无痕窗口的成功手工对照，因此不能简单归因于“手工是普通窗口、插件是无痕”。不同账号、时间和服务端策略仍是未控制因素，当前没有足够证据定位单一原因。

实际托管链路存在于 `app/integrations/openai/browser/signup.py` 与 `signup_bridge.js`：CDP 创建隔离上下文并加载共享 content.js，宿主处理消息和注册完成交接；当前输入仍是该脚本的 DOM 事件。此前称 Python 未调用托管路径的说法不正确。

本轮仅完成此架构检查，没有实现 CDP 输入替换，也不提供以绕过手机号验证为目的的行为伪装。更换事件来源不代表可以免除验证。遇到手机验证继续保留暂停和人工处理。

- 另有 20 个现有浏览器用例通过，包括表单约束、键盘监听隔离、提交去重、短暂加载、手工提交、自动/核对完整扩展流程、托管注册交接和手机验证暂停。其中 19 项批次日志在 `dist/signup-038-validation/regression.log`；另 1 项 OTP 自动跳页与新用例一起单独运行。
- Node 后台与邮件测试 22 项通过。
- Python 托管状态和浏览器交接单元测试 29 项通过。
- JavaScript 语法检查与 Python 测试文件编译检查通过。

前面实验版本的全量测试结果不能替代最终版本结果；最终版本采用上述针对性验证，没有重新跑完整项目测试或构建 Docker 镜像。没有使用真实账号重新注册或授权，没有连接或部署 VPS，不能证明手机号验证概率变化。

## 安装

使用本机已有配置重新构建：

```powershell
.\.venv\Scripts\python.exe scripts/build_signup_extension.py --local-config --unpack
```

交付目录 `dist/chatgpt-signup/`；安装包 `dist/team48-chatgpt-signup-0.3.8-personal.zip`。本轮会覆盖此前实验性的同版本安装包，使用者需重新覆盖并在扩展管理页重新加载。关闭旧注册页后开始新任务，弹窗与进度卡片应显示 0.3.8。仅更新磁盘文件不会自动刷新正在运行的扩展。
